版本：v0.3（最终修订版）

作者：产品/技术团队

## 1. 产品概述

### 1.1 名称释义
“Zoosy”取自中文“主思”的谐音，意为“主动思考”。核心理念：在用户完成某项活动（观影、阅读、运动等），或可能被网络舆论影响时，以温和、朋友式的问候，邀请用户进行独立的、轻量的思考与记录，帮助用户抵抗算法推荐与情绪化舆论对个人判断力的侵蚀。

### 1.2 核心价值主张
- 帮助用户建立“体验/接触 → 独立思考 → 轻量记录”的闭环习惯。
- 弱化外部声音（营销号、KOL、极端情绪）对用户独立判断的影响。
- 长期沉淀用户自己的“思考档案”，形成个人认知成长史。
- **核心创新**：将“消息通知”转化为有价值的“思考邀请函”，通过精妙的时机匹配和温暖通用的文案，解决“记录行为无意义感”和“容易被舆论裹挟”的双重痛点。

### 1.3 目标用户
- 有自我反思习惯诉求、但缺乏轻量工具的年轻用户（学生、职场新人）。
- 容易被网络评分、热搜、评论影响，希望保持独立思考的网民。
- 对舆论极化、信息茧房感到疲惫，希望“冷处理”热点事件的用户。

## 2. 核心场景与需求

### 2.1 触发场景（事件类型，MVP阶段固定，不开放自定义）
| 事件大类 | 示例 | 思考维度示例 |
|---|---|---|
| **影视/阅读** | 看完一部电影、一集剧、一本书 | 真实感受 vs. 网络评分？哪个细节被夸大了/低估了？ |
| **运动/健康** | 完成一次跑步、健身、早睡 | 身体感受？是否达到自己的小目标？ |
| **待办/任务** | 完成一项工作、学习任务 | 完成质量？过程中的意外收获？ |
| **舆论/热点** | 刷到一个热搜、参与一个讨论、看到一则争议新闻 | 我了解事实全貌吗？我的情绪来源是什么？是否存在“站队”冲动？ |

> **重要**：v0.3 取消用户自定义大类，产品初期聚焦于预设的、最高频的四个思考场景。

### 2.2 关键问题一：如何知道用户“完成了某件事”或“适合被邀请思考”？

#### 对于行为类事件（影视、运动、待办）：
以手动打卡为主，未来可选的日历联动。用户可主动记录。

#### 对于通用思考邀请（覆盖包括舆论在内的所有场景）：
推送定位为**温柔的“思考邀请函”**，而非“事件感知报告”。

**智能推送时机算法**

- **所需权限**：通知权限（必须）；设备使用情况访问权限（Android可选，用于判断使用时长）。
- **数据原则**：所有计算均在本地完成，不上传任何浏览记录、剪贴板内容。
- **推送触发条件（满足任一，且不在抑制条件内）**：
  1. **时长触发**：用户连续使用新闻/社交/视频类App超过 **15分钟**（可配置），退出后 **2分钟内**，且距离上次推送超过 **6小时**。
  2. **行为触发**：用户进行了“转发、评论、长按点赞”等深度互动（通过无障碍服务或使用情况API推测，需用户授权）。
  3. **剪贴板触发**：用户复制了长度 > 50 字的文本（典型的话题/新闻），且过去1小时内未因剪贴板触发过。
  4. **时间习惯触发**：在用户常用的睡前时间段（如22:00-23:00），若当天尚未进行任何记录，发送一条温和提醒。

- **抑制条件（不推送）**：
  - 勿扰模式或睡眠时段（用户自定义）。
  - 过去1小时内已记录过一条思考卡。
  - 用户连续忽略同类推送 **3次**，则未来7天内降低该触发源的权重。

- **推送文案（固定，亲切通用）**：
  > **标题**：Zooby 想你了  
  > **内容**：hello，最近在干什么？需要停下来思考一下吗？

  > *备选文案（随机轮换，避免审美疲劳）*：  
  > - “嗨，今天有什么值得记下来的瞬间吗？”  
  > - “要不要花30秒，只为自己写一句话？”  
  > - “刚刚忙完一段了吧？来，深呼吸，记录一下真实感受。”

- **点击通知后的行为**：
  - 打开 App 进入一个**极简选择页**，显示四个类别卡片（影视阅读、运动健康、待办任务、舆论热点），并配问题：“最近让你印象最深的一件事是什么？”
  - 用户选择类别后，进入该类别的思考模板页（一句话模式或完整模式）。
  - **完全避免**自动填入任何“感知到的具体事件名”，把命名的自由和反思的起点还给用户。

- **用户控制**：  
  在设置中，用户可以：
  - 完全关闭“智能感知推送”
  - 分别开关“时长触发”“行为触发”“剪贴板触发”“睡前提醒”
  - 调整触发时长阈值（如改为10分钟或20分钟）

> **设计理念**：放弃猜测用户具体关注话题，避免隐私风险与防御心理。通用问候 + 用户自选类别，尊重隐私，强调“主动思考”——主题由用户自己决定。

### 2.3 关键问题二：思考记录的内容结构

每条记录（“思考卡”）基础结构如下：

- 事件类别（固定四类：影视阅读、运动健康、待办任务、舆论热点）
- 事件名称（用户填写）
- 发生时间（用户选择）
- 记录时间（系统自动）
- **核心思考问题**（按类别提供模板化问题，用户可编辑答案，问题本身不可编辑）

**舆论类默认思考问题模板**：
1. **事实厘清**：关于这件事，我**确实知道**的事实有哪些？（而不是我听说或推测的）
2. **情绪识别**：我现在的第一情绪是什么？（愤怒/兴奋/悲伤/焦虑/有趣……）这个情绪是被什么信息点燃的？
3. **立场审视**：在我形成看法前，我是否已经无意中偏向某一方？为什么？
4. **行动评估**：我有没有想要立即转发、评论或站队的冲动？如果有，记录下这个冲动，然后问自己：等30分钟后再做决定，会有什么不同？
5. **独立判断**：抛开所有大V和热评，**我自己**此刻的真实想法是什么？（一句话总结）

**其他类别模板**（保留原风格，加入与网络主流观点差异的反思）：
- 影视类：这部电影你最喜欢的一点是什么？有没有哪个地方让你觉得“和网上说的不一样”？
- 阅读类：收获了什么？是否值得推荐？书中观点你完全同意吗？
- 运动/健康类：身体感受如何？是否达到目标？下次如何改进？
- 待办类：完成质量如何？过程中遇到什么？学到了什么？

- 自由文字记录（可选，富文本）
- 心情/评分（可选，5分制或表情）
- 标签（自定义，用于检索）
- 附件（图片，可选）
- 隐私级别（仅自己可见/可分享）

### 2.4 关键问题三：如何让用户持续记录（留存与习惯养成机制）

#### 2.4.1 降低记录成本
- “思考卡”填写时间控制在30秒~2分钟（默认只需选1-2个核心问题作答）
- 语音转文字输入
- “一句话记录”模式

#### 2.4.2 即时反馈与成长可视化
- 每次记录后正反馈（连续天数、本月数量）
- “思考足迹”时间轴
- 月度/年度回顾报告

#### 2.4.3 习惯养成机制
- 连续打卡天数（Streak），允许补记，避免惩罚式设计
- 智能提醒（基于历史时间段）
- “冷静期回访”与“时间胶囊”对比回顾

**冷静期回访推送文案**（针对已记录用户）：
- 24小时后：> “关于你昨天记下的那件事，今天有什么新感受吗？哪怕只是变了一点点。”
- 一个月后：> “一个月前你曾思考过【事件名称】，现在回头看，想补充点什么吗？”

#### 2.4.4 社区与分享（可选，MVP不做）

### 2.5 隐私与数据安全
- 所有记录默认本地存储 + 云同步（端到端可选加密）
- 不强制注册即可使用核心功能（本地优先）
- 敏感权限明确告知、可随时关闭，不上传原始行为数据
- **使用情况访问权限**：仅用于本地判断使用时长，不上报具体内容
- **剪贴板读取**：用户授权后仅检测复制行为，不读取内容（或可读取但不离开设备）

## 3. 信息架构与页面规划（MVP）

### 3.1 主要页面
1. **首页 / 思考足迹（时间轴）**：按时间排序的思考卡列表，快捷打卡入口，统计概览
2. **新建思考卡页**：选择固定四类 → 填写事件信息 → 展示专属思考模板 → 保存；支持极简/完整模式切换
3. **类别管理页（简化）**：仅支持对预置四个类别的启用/停用、排序、修改图标/颜色，无自定义类目
4. **统计/回顾页**：月度/年度回顾，时间胶囊对比入口，标签云，类别分布图
5. **提醒与通知设置页**：基础习惯提醒，智能感知推送开关及各子开关，勿扰模式
6. **设置页**：账号、同步、隐私权限、主题等
7. **思考卡详情页**：查看/编辑，对比回顾入口

## 4. 技术架构建议

### 4.1 跨平台前端
- 推荐 **Flutter**，一套代码覆盖 Android/iOS/HarmonyOS（关注鸿蒙适配进展）
- 响应式布局，适配手机、折叠屏、平板；支持暗色模式

### 4.2 后端架构
- Node.js (NestJS) 或 Python (FastAPI)
- PostgreSQL + 本地 SQLite（离线优先，增量同步）
- 认证：手机号/邮箱 + 第三方登录（国内考虑微信）
- 推送：Android（FCM或厂商通道）、HarmonyOS（Push Kit）、iOS（APNs）

### 4.3 客户端本地智能引擎
- 轻量级状态机维护推送冷却、忽略计数等，不上传用户行为详情
- 算法逻辑全部客户端运行

### 4.4 数据模型（核心实体）
- User, Category（固定四个，系统预置，不可新增自定义类别）, ThoughtCard（含舆论类专属字段如 emotionTags, controversyTopic 用户自填）, PlanEvent（可选）

## 5. MVP 范围建议（第一阶段）

1. ✅ 手动打卡 + 思考卡记录（四个固定类别，含舆论专属模板）
2. ✅ 时间轴展示 + 详情查看/编辑
3. ✅ 本地存储 + 简单账号体系 + 云同步
4. ✅ 基础习惯提醒（固定时间）
5. ✅ **通过分享链接或手动选择类别创建“舆论观察”卡片**（作为舆论感知的MVP入口）
6. ✅ Android 单端，响应式布局

**第二阶段（V1.0）**：
- 智能舆论感知推送（时长/行为/剪贴板触发，通用文案）
- 冷静期回访推送
- 月度回顾报告
- iOS / HarmonyOS 移植

**第三阶段（V2.0）**：
- 时间胶囊对比回顾
- 更丰富的统计
- 可选思考广场（无社交压力）
